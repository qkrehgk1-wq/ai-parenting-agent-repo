# Upgrade Rhythm

## 목적

기능 업그레이드 팀은 최신 AI 흐름을 따라가되, 우리 서비스에 맞는 것만 선별적으로 도입하는 역할을 맡는다.

핵심 원칙은 세 가지다.

- 최신 기술을 무조건 빠르게 넣지 않는다.
- 운영 안정성과 부모 신뢰를 먼저 본다.
- 작은 실험으로 검증한 뒤 정식 반영한다.

## 권장 운영 주기

### 주간

- 운영 중 불편 사례 수집
- 반복 실패 패턴 정리
- 새 도구 또는 모델 후보 메모

### 월간

- `type:upgrade` 이슈 3~5개 선정
- 실험 우선순위 결정
- 실험 PR 생성

### 분기

- 핵심 에이전트 프롬프트 재검토
- 모델 구성 재검토
- MCP 도구 활용 범위 재설계
- 성능, 품질, 안전 지표 비교

## 업그레이드 우선순위 기준

1. 부모에게 전달되는 정보의 품질이 좋아지는가
2. 검수와 안전성이 유지되거나 더 좋아지는가
3. 창업자의 운영 시간이 줄어드는가
4. GitHub MCP 기반 추적 가능성이 유지되는가
5. 실패했을 때 쉽게 롤백 가능한가

## GitHub 운영 방식

- 업그레이드 안건은 반드시 `type:upgrade` 이슈로 등록
- 작은 실험은 기능 브랜치에서 진행
- 운영 영향이 큰 변경은 별도 PR로 분리
- 실험 종료 후 결과를 이슈 코멘트로 남김

# Demo Upgrade Experiment 001

## 실험명

GitHub MCP 기반 PR 자동 요약 및 리뷰 병목 감지

## 목적

대표 에이전트와 안전 검수 에이전트가 PR 상태를 더 빠르게 파악하도록 돕는 보조 루프를 만든다.

## 배경

현재 운영 구조는 이미 GitHub 이슈와 PR 중심으로 잘 짜여 있다.
하지만 PR 수가 늘어나면 아래 문제가 반복될 가능성이 높다.

- PR을 읽는 시작 비용이 커진다.
- 막힌 PR과 진행 가능한 PR을 빠르게 구분하기 어렵다.
- 대표 에이전트가 우선순위를 판단하는 시간이 길어진다.

## 실험 범위

이번 실험에서는 실제 자동 실행 코드까지 만들기보다, 운영 문서와 에이전트 출력 형식을 먼저 정의한다.

실험 대상:

- 대표 에이전트
- 안전 검수 에이전트
- 업그레이드 에이전트

## 제안 출력 형식

### PR 자동 요약 형식

- PR 제목:
- 관련 이슈:
- 핵심 변경:
- 검토 포인트:
- 남은 리스크:
- 배포 가능 여부:

### 리뷰 병목 감지 형식

- unresolved 리뷰 스레드 수:
- 가장 중요한 막힘:
- 필요한 다음 액션:
- 대표 승인 필요 여부:

## GitHub MCP 사용 흐름

1. `_get_pr_info`
   PR 제목, 상태, base/head 확인

2. `_fetch_pr`
   변경 파일과 PR 설명 문맥 파악

3. `_list_pull_request_review_threads`
   unresolved 리뷰 스레드와 실제 막힘 확인

4. `_add_comment_to_issue`
   업그레이드 실험 결과와 다음 액션 기록

## 기대 효과

- 대표 에이전트가 PR 우선순위를 더 빠르게 결정
- 안전 검수 에이전트가 남은 수정 사항을 빠르게 파악
- 주간 운영 리포트의 기초 데이터 확보

## 성공 판단 기준

- 사람이 직접 읽은 결론과 자동 요약 결과가 대체로 일치
- 막힌 PR을 빠르게 구분할 수 있음
- PR당 판단 시간이 줄어듦

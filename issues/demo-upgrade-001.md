# Demo Upgrade Issue 001

## 제목

[업그레이드] GitHub MCP 기반 PR 자동 요약 및 리뷰 병목 감지 루프 도입

## 라벨

- `type:upgrade`
- `status:research`
- `priority:high`

## 현재 문제

콘텐츠와 운영 문서가 늘어날수록 대표 에이전트와 검수 에이전트가 PR을 처음부터 끝까지 직접 훑어야 하는 부담이 커진다.

현재 구조만으로도 운영은 가능하지만, 아래 같은 병목이 생길 수 있다.

- 어떤 PR이 왜 중요한지 한눈에 파악하기 어렵다.
- unresolved 리뷰 스레드가 남아 있는지 매번 수동 확인해야 한다.
- 대표 에이전트가 여러 PR 중 무엇부터 봐야 할지 우선순위를 잡는 데 시간이 든다.
- 업그레이드 제안 PR과 콘텐츠 PR이 섞이면 운영 집중도가 떨어질 수 있다.

## 업그레이드 아이디어

GitHub MCP를 활용해 아래 2가지 기능을 먼저 실험한다.

1. PR 자동 요약
   - `_get_pr_info`, `_fetch_pr`를 기반으로 PR 목적, 변경 파일, 검수 포인트, 남은 리스크를 자동 정리

2. 리뷰 병목 감지
   - `_list_pull_request_review_threads`를 기반으로 unresolved 리뷰 스레드 유무와 막힌 이유를 자동 요약

## 업그레이드 범위

- MCP 활용
- 자동화 워크플로우
- GitHub 운영 방식

## 운영 영향도

중간

## 기대 효과

- 대표 에이전트가 PR 상태를 더 빠르게 이해할 수 있다.
- 검수 대기 PR과 실제 막힌 PR을 구분할 수 있다.
- 배포 전 unresolved 리뷰 스레드 확인이 쉬워진다.
- 향후 주간 운영 리포트 자동화의 기반이 된다.

## 성공 기준

- PR마다 5줄 이내의 요약을 자동 생성할 수 있다.
- unresolved 리뷰 스레드가 있는 PR을 자동으로 표시할 수 있다.
- 대표 에이전트의 PR 1건당 확인 시간을 줄일 수 있다.
- 업그레이드 팀이 월간 리포트에 반영 가능한 수준의 운영 데이터를 남길 수 있다.

## 롤백 조건

- 자동 요약이 핵심 리스크를 자주 놓칠 경우
- 병목 탐지가 실제 리뷰 상태와 자주 어긋날 경우
- 오히려 사람이 다시 전체 PR을 처음부터 읽어야 해 시간이 더 늘어날 경우

## Upgrade Agent 메모

첫 업그레이드 안건으로 적합하다.
이 기능은 부모에게 직접 노출되는 기능이 아니므로 상대적으로 안전하게 실험할 수 있고, 이후 모든 에이전트 운영 효율에 영향을 줄 수 있다.
